## User Requirements
用户询问「开门成功的蓝牙名称，以及日志持久化可行吗」，经澄清后确认要落地实现两项能力，且已明确选择具体方案：
- 设备名称：使用系统 BLE 名称（尝试读取 `BluetoothDevice.name`）；因本项目按 MAC 直连、不扫描，取不到时显示为空或脱敏 MAC，接受该不确定性。不要自定义备注名、不要引入扫描。
- 日志：完整运行日志按「每次开门一个会话」保存，包含逐步 BLE 日志与开门结果，支持翻看历史会话。
- 展示位置：仅扩展主页现有可折叠的「运行日志」卡片；不改快捷方式结果卡、桌面小部件，也不做「仅保存不展示」。

## Product Overview
在现有离线蓝牙门禁 App 中，为每次开门留下可追溯记录：主页日志卡片除显示本次实时日志外，还能切换查看历次开门会话。每个会话头部显示时间、开门结果、耗时与当时连接到的蓝牙设备名称（无法获取时降级为脱敏 MAC），下方逐行展示该次开门的连接、发现服务、读取挑战码、写入密钥等全过程日志。视觉上沿用现有 Material 3 卡片、等宽字体日志行与折叠动画，新增轻量的会话选择条、结果摘要行以及复制、清空历史操作。

## Core Features
- 开门成功（以及失败、取消）时记录系统蓝牙名称，取不到则降级显示脱敏 MAC。
- 运行日志按会话持久化到本机，App 重启或进程回收后仍可查看。
- 主页日志面板可切换历次会话，查看该次摘要与完整逐步日志，并支持复制与清空历史。
- 历史记录有数量与行数上限，自动轮转；日志与设备名称排除云备份与换机迁移；不新增任何权限、不引入蓝牙扫描、不联网。

## Implementation Approach
**策略**：把「一次开门」建模为 `LogSession`，新建 `LogRepo` 作为会话的唯一数据源（内存 `StateFlow` + 本地文件）；`UnlockRepo` 仅在 `begin / append / finish` 三个节点接入，BLE 状态机、看门狗、GATT 回调与 `DataRepo.saveLastResult()` / `WidgetRefresher.refresh()` 主链路完全不动。

**设备名称**：`unlock()` 中 `adapter.getRemoteDevice()` 后先尝试一次 `runCatching { device.name }`；`onConnectionStateChange` 连接成功后若仍为空，再从 `gatt.device.name` 补读一次（蓝牙栈缓存可能此时才填充）。结果写入 `LogSession.deviceName`，取不到时 UI 显示「名称未获取到」并附 `DeviceConfig.maskMac()`。用 `runCatching` 兜住 `SecurityException`；不扫描、不加权限。

**落盘**：`filesDir/unlock_logs/<19 位 startedAt>.log`，文件为「固定头部元数据行 + 一行一条日志」的纯文本。`begin` 在 IO 线程写一次占位文件，`finish` 覆盖写完整会话；`log()` 只做内存 `append`，不触碰磁盘。同一会话的两次写由单线程 IO 调度保证顺序。

**关键决策与权衡**：
- 不用 SharedPreferences 存日志：多行大文本会让 SP 每次读写整份 XML，`data.xml` 还含 MAC/Key，混入会放大解析开销与泄露面；独立文件覆盖写更直接。
- 不用 JSON：无序列化依赖，纯文本头部 + 日志行零依赖、可读、可直接复制。
- 历史会话全量加载到内存：上限 20 会话 × 60 行（<100KB），启动时一次异步加载换取 UI 直接 `collect` 单一 `StateFlow`，避免按需 suspend 读取带来的加载态与并发复杂度。
- 保留 `UnlockRepo.logs`（含 `Log.d` 与 60 行上限）以兼容现有公开 API、零回归；`MainView` 改为消费 `LogRepo.sessions` 这一单一数据源，实时性由 `append` 同步更新进行中会话的 `lines` 保证。
- 不改 `UnlockState.kt` / `LastUnlock` / `DataRepo.kt` / 小部件 / `ShortcutResultView.kt`，把变更半径限制在 6 个文件内。

**性能与可靠性**：`append` O(1)；磁盘写 2 次/会话且全部在 `Dispatchers.IO`，不阻塞运行于 `Main.immediate` 的 GATT 回调；轮转列目录 + 删旧文件 O(20)，文件名即定长时间戳，字典序等于时间序；UI 仅在面板展开时渲染「选中会话」的 ≤60 行，避免一次渲染上千行；进程在开门途中被杀仍留下 `RUNNING` 占位会话，重启后可标记为「中断」；读取用 `runCatching` 跳过损坏/旧格式文件，绝不影响启动。

## Implementation Notes
- `log()` 中现有 `Log.d(TAG, message)` 保持不变；设备名称本身**不写进 logcat**，只记录「名称已获取 / 未获取」，名称仅存本地文件与 UI，最小化 PII 面。现有日志已不含 Key 明文、挑战码内容（只有 size），MAC 已脱敏。
- 落盘前把每行的 `\n` / `\r` 替换为空格：`fail(detail)` 可能来自异常 `message`，必须保证「一行一条」格式不被破坏。
- `fail(persist = false)`（未配置、格式错误、无权限、蓝牙未开等前置失败）同样要 `finish()` 记录会话，但不写 `LastResult`、不刷新小部件；`unlock()` 因「已有任务进行中」早退时 `append` 找不到活跃会话需静默容错；`cancel()` 也要 `finish(CANCELLED)`；`closeGatt()` 逻辑不动。
- 备份：`backup_rules.xml` 与 `data_extraction_rules.xml` 增加对 `unlock_logs` 目录的显式排除（与现有 `sharedpref/data.xml` 排除同构，`cloud-backup` 与 `device-transfer` 两节都要加），不依赖 `noBackupFilesDir` 在换机迁移上的行为差异。
- 兼容旧数据：无历史文件时 `sessions` 为空，UI 显示原有空态文案；`LogRepo` 惰性初始化，不在 `Application.onCreate` 增加启动 IO。
- 验证：仓库无 `src/test` / `src/androidTest`（README 第 81 行），以 `gradlew.bat :app:assembleDebug` 编译 + 人工路径检查为准：主页开门、快捷方式开门、前置失败、超时失败、用户取消、重启后翻看历史、复制、清空、备份排除规则生效。

## Architecture Design
分层保持现状：`compose/` 只负责展示，`unlock/` 负责状态机与持久化，`util/` 提供格式化与脱敏，`widget/` 不变。

数据流：
`MainActivity / ShortcutActivity → UnlockRepo.unlock() → BLE GATT 回调 → log()` 分两路：一路保留 `Log.d` 与 `_logs`（兼容），另一路 `LogRepo.begin/append/finish` → `LogRepo.sessions: StateFlow` → `MainView.LogPanel`。
`LogRepo` 在 IO 线程读写 `filesDir/unlock_logs/*.log` 并做轮转；`succeed()/fail()/cancel()` 另外维持原有 `DataRepo.saveLastResult()` → `WidgetRefresher.refresh()` → Glance 小部件链路，互不干扰。组件关系简单，无需引入新架构模式或图示。

## Key Code Structures
```kotlin
// LogRepo.kt：多模块共享的会话模型（同包引用 UnlockFailure）
enum class LogOutcome { RUNNING, SUCCESS, FAILED, CANCELLED }

data class LogSession(
    val id: Long,                       // startedAt 毫秒，兼作文件名
    val startedAt: Long,
    val outcome: LogOutcome = LogOutcome.RUNNING,
    val endedAt: Long? = null,
    val reason: UnlockFailure? = null,
    val detail: String? = null,
    val deviceName: String? = null,     // 系统 BLE 名称，可为 null
    val macLabel: String = "",          // DeviceConfig.maskMac 结果，名称缺失时降级展示
    val elapsedMs: Long = 0L,
    val lines: List<String> = emptyList()
)

// LogRepo 对外契约（均为接口级签名，无实现体）
object LogRepo {
    val sessions: StateFlow<List<LogSession>>   // 按 startedAt 倒序，含进行中会话
    fun begin(id: Long, startedAt: Long, macLabel: String, deviceName: String?)
    fun append(sessionId: Long, line: String)
    fun finish(sessionId: Long, outcome: LogOutcome, endedAt: Long, elapsedMs: Long,
               reason: UnlockFailure? = null, detail: String? = null)
    fun clear()
}
```
